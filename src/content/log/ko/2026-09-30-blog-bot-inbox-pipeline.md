## 무엇을 했나

기존에 쓰던 블로그 봇을 정적 사이트 블로그에서도 쓸 수 있게 바꿨다. 목표는 두 가지였다. 봇이 새 블로그에 글을 올릴 수 있어야 하고, 작업하면서 겪은 일이 저절로 글감으로 쌓여야 한다.

시작하자마자 두 군데서 막혔다.

첫째, 사이트 저장소가 공개 상태였다. 저장소 설정에서 직접 확인했다. 가공하지 않은 메모를 저장소에 커밋하면 그대로 외부에 공개된다.

둘째, 기존 봇에는 내가 겪은 일을 넣을 입구가 없었다. 원래 정부지원금 사이트에 글을 올리려고 만든 설치형 CMS용 파이프라인이었고, 주제를 먼저 정한 뒤 글을 생성하는 구조였다.

글 형식도 따로 확인했다. 사이트의 `content.config.ts` 스키마가 frontmatter 형식을 강제한다. 설명은 20~160자여야 하고, 검증일지에는 판정과 출처가 반드시 있어야 한다. 봇이 만든 글도 이 조건을 통과해야 한다.

위 내용을 바탕으로 이렇게 정했다.

| 항목 | 결정 |
|---|---|
| 메모 저장 위치 | 사이트 저장소 안의 git 제외 폴더(`_inbox`) |
| 메모 작성 규칙 | 모든 작업 세션에 공통 규칙 적용. 검증·실험·실패·구축 네 가지 경우에만 정해진 형식으로 남김 |
| 봇 흐름 | 메모 → 초안(사람 검수용 파일) → 품질 게이트 → 발행 |
| 기본 동작 | 초안까지만 만든다 |
| 기존 파이프라인 | 지우지 않고 정적 사이트 경로를 옆에 추가 |
| 글 생성 수단 | 이미 구독 중인 AI 도구의 CLI |

메모 폴더는 git에서 제외했기 때문에 공개 저장소에 올라가지 않는다. 그래도 사이트 저장소 안에 있어서 봇은 같은 경로에서 메모를 바로 읽는다. 공개 문제와 입구 문제를 폴더 하나로 같이 해결했다.

발행은 git push로 한다. push하면 곧바로 배포되기 때문에 기본값을 초안 생성까지로 막아 두었다. 사람이 초안을 보고 품질 게이트를 통과한 글만 올라간다.

## 결과

추가로 든 비용은 0원이다. 글 생성에는 이미 쓰고 있는 구독 도구의 CLI를 쓰기 때문에 새로 결제한 것이 없다. 매출도 아직 0원이다. 이번 작업은 글을 쌓을 구조를 만든 것까지이고, 글이 실제로 발행되어 성과가 나오는 단계는 아직 오지 않았다.

작업 시간은 기록해 두지 않아서 표에 "-"로 적었다. 이번 작업에서 실패로 센 건은 0건이다.

사람 검수를 넣고도 한 편에 10분 안쪽으로 끝나면 주 3편은 발행할 수 있을 것 같다. 다만 이건 추측이다. 아직 재 본 숫자가 없어서 판단 근거로 쓰지 않는다.
