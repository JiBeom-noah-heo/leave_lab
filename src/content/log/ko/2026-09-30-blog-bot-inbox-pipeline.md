## 무엇을 했나

기존에 쓰던 블로그 봇을 정적 사이트 블로그에서도 쓸 수 있게 바꿨다. 목표는 두 가지였다. 새 블로그에도 같은 봇을 사용할 수 있어야 하고, 작업 과정에서 생긴 경험이 자연스럽게 글감으로 쌓여야 했다.

시작하자마자 두 군데서 막혔다.

첫째, 사이트 저장소가 공개 상태였다. 저장소 설정에서 직접 확인했다. 가공하지 않은 메모를 저장소에 커밋하면 그대로 외부에 공개된다.

둘째, 기존 봇에는 작업 경험을 기록할 수 있는 입력 경로가 없었다. 원래 정부지원금 사이트에 글을 올리려고 만든 설치형 CMS용 파이프라인이었고, 주제를 먼저 정한 뒤 글을 생성하는 구조였다.

글 형식도 따로 확인했다. 사이트는 `content.config.ts`에서 글 메타데이터(frontmatter) 형식을 검증한다. 설명은 20~160자여야 하고, 검증일지에는 판정과 출처가 반드시 있어야 한다. 봇이 만든 글도 이 조건을 통과해야 한다.

위 내용을 바탕으로 이렇게 정했다.

| 항목 | 결정 |
|---|---|
| 메모 저장 위치 | 사이트 저장소 안의 git 제외 폴더(`_inbox`) |
| 메모 작성 규칙 | 모든 작업 세션에 공통 규칙 적용. 검증·실험·실패·구축 네 가지 경우에만 정해진 형식으로 남김 |
| 봇 흐름 | 메모 → 초안(사람 검수용 파일) → 품질 게이트 → 발행 |
| 기본 동작 | 초안까지만 만든다 |
| 기존 파이프라인 | 지우지 않고 정적 사이트 경로를 옆에 추가 |
| 글 생성 수단 | 이미 구독 중인 AI 도구의 CLI |

메모 폴더는 git에서 제외했기 때문에 공개 저장소에 올라가지 않는다. 그래도 사이트 저장소 안에 있어서 봇은 같은 경로에서 메모를 바로 읽는다. 공개 저장소 노출 문제와 메모 입력 경로 문제를 폴더 하나로 동시에 해결했다.

발행은 git push로 한다. push하면 곧바로 배포되기 때문에 기본값을 초안 생성까지로 막아 두었다. 사람이 초안을 보고 품질 게이트를 통과한 글만 올라간다.

## 결과

추가로 든 비용은 0원이다. 글 생성에는 이미 쓰고 있는 구독 도구의 CLI를 쓰기 때문에 새로 결제한 것이 없다. 매출도 아직 0원이다. 이번 작업은 글을 쌓을 구조를 만든 것까지이고, 글이 실제로 발행되어 성과가 나오는 단계는 아직 오지 않았다.

작업 시간은 기록해 두지 않아서 표에 "-"로 적었다. 실패로 분류한 건은 없었다.

사람 검수를 넣고도 한 편에 10분 안쪽으로 끝나면 주 3편은 발행할 수 있을 것 같다. 다만 아직 실제 측정값은 없다. 초안 검수 시간을 재 보기 전까지는 가설로만 둔다.

## 다음 행동

메모가 5개 쌓이면 초안을 생성하고, 검수 시간·수정 횟수·최종 발행 여부를 기록한다.

## 정리

**측정한 것**
- 비용: 0원 (이미 구독 중인 AI 도구의 CLI 사용)
- 시간: 기록하지 않음
- 결과: 메모 → 초안 → 품질 게이트 → 발행 흐름을 만들었다. 매출은 0원

**확실한 것**
- 메모 폴더(`_inbox`)는 git에서 제외되어 공개 저장소에 올라가지 않는다.
- 봇이 만든 글도 사이트의 메타데이터 검증(설명 20~160자, 검증일지는 판정·출처 필수)을 통과해야 발행된다.

**아직 모르는 것**
- 사람 검수를 넣었을 때 글 한 편에 걸리는 시간
- 그 시간으로 주 3편 발행이 가능한지
