## 무엇을 했나

작업 메모를 블로그 글로 만드는 도구를 만들었다. 매번 사람이 발행 버튼을 누르지 않아도, 메모에 없는 내용을 덧붙이지 않고 자동으로 발행할 수 있는지 확인하고 싶었다.

만들면서 세 군데에서 막혔다.

- **메모에 없는 내용:** 사람 검수 없이 자동 발행하면 AI가 메모에 없는 사실, 숫자, 인과관계 등을 덧붙여도 그대로 공개된다.
- **메모가 또 메모를 남기는 문제:** 글을 만드는 AI도 "작업이 끝나면 메모를 남겨라"는 공통 규칙을 읽는다. 그래서 글을 쓰는 과정에서 메모 폴더에 또 다른 메모를 남길 가능성이 있었다.
- **검토 시간 문제:** 하루에 한 번 실행하면서 검토 시간을 정확히 24시간으로 두면, 실행 시각이 몇 초만 빨라도 발행이 하루 밀릴 수 있었다.

정리한 흐름은 다음과 같다.

| 단계 | 내용 |
|---|---|
| 1. 초안 | 메모로 초안을 만든다 |
| 2. 자체 검토 | 문제를 찾으면 수정한다 |
| 3. 검토 시간 | 약 24시간 기다린다 |
| 4. 형식 검사 + 사실 검증 | 메모와 대조한다 |
| 5. 발행 | 검증에서 걸리면 자동 수정(최대 2회) 후 다음 날 다시 검증한다 |

글을 만드는 AI 호출은 도구를 모두 꺼서 파일을 쓸 수 없게 했다. 검토 시간은 24시간으로 두되 판정에 1시간 여유를 둬서, 실제로는 23시간이 지나면 발행 대상이 된다. 매일 09:00에 실행되므로 실행 시각이 조금 당겨져도 다음 날 실행 때 처리된다. 비용은 0원이다. 이미 구독 중인 CLI를 쓴다.

## 결과

사실 검증 단계를 세 가지로 시험했다.

| 시험 | 결과 |
|---|---|
| 메모에 없는 숫자 2개(작업 시간, 방문자 수)와 상품명 1개를 일부러 넣은 초안 | 3개 모두 지적 |
| 문제없다고 생각한 원본 초안 | 메모에 없는 인과관계 문장 3개 지적 |
| 시험용 검증일지(한국어+태국어) | 발행 단계에서 두 번 걸렸고 자동 수정 2회 뒤 통과, 사이트 빌드도 통과 |

일부러 넣은 오류는 모두 잡혔다. 특히 두 번째 시험이 의미 있었다. 내가 직접 읽었을 때는 문제없다고 생각한 초안에서도 메모에 없는 인과관계를 찾아냈다.

다만 검증 기준이 엄격해, 메모에 근거가 있더라도 단정적으로 표현한 문장까지 지적하는 경우가 있었다. 자동 수정을 두 번 하고 나서야 통과한 경우도 있었다.

첫 실전 초안은 다른 작업 세션이 공통 규칙대로 남긴 메모였다. 워치 앱 배터리 실험 메모다.

이번 실험에서는 자동 발행 시스템 자체의 안전성을 확인하기 위해 첫 몇 편은 직접 읽어 본다. 이후에는 사람 검수 없이도 같은 품질이 유지되는지 확인할 예정이다.

## 다음 행동

첫 자동 발행 글 몇 편을 직접 읽고, 검증이 너무 엄격해서 글이 밋밋해지지 않는지 확인한다. 수정 횟수와 실제 검수 시간도 함께 기록한다.
